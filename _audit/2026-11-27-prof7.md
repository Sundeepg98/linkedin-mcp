## 1. SELF-LOADER-WAITS-FOR-THE-REWRITE (first, red first)

The orchestrator's order of 2026-11-26 22:21, from session 12's E1 refusal.

### 1.1 The mechanism, as measured live (session 12's record, E1)

* `linkedin_my_activity_items` refused his own profile
  `self_assertion_unreadable` after 2 loads; its evidence, in closed words:
  url marker absent, `landed_on_member_path` false, structure not read.
* The dedicated profile's history (a copy, closed classes only): the self
  alias visited, then his member path about one second later as a SEPARATE
  link-type visit with no redirect qualifier. LinkedIn serves `/in/me/` as its
  own document and rewrites the address CLIENT-SIDE.
* The shipped loader read the landing before the rewrite: `BROWSER.goto`
  returns `page.url` once its settle ends, and the settle can end on a 500 ms
  network lull before the rewrite lands. It saw the self alias, which
  `self_profile.landed_member_segment` refuses to treat as a member, and
  refused -- fail closed, as designed.

### 1.2 The fix

| where | what |
|---|---|
| `self_profile.on_self_alias`, `awaits_rewrite` | PURE: the alias's own profile root on LinkedIn's host; and that root carrying NO marker -- the one landing waited on. A landing the marker answered is decided by the marker, untouched; a member path has already arrived. |
| `self_profile.await_rewrite` | waits, bounded by `SELF_REWRITE_BOUND_S` (5.0 s, five times the measured gap), looking every `SELF_REWRITE_POLL_S` (0.25 s), while `page.url` is still the alias. Reads ONLY `url` (asserted on its own syntax tree); never navigates, reloads, runs a script or presses; never raises; answers in closed words (`not_needed`, `arrived`, `not_within_bound`, `unreadable`) and integers, never the address. |
| `server._goto_self_profile_asserted` | after each load, if the landing awaits the rewrite: the wait, then `page.url` read again, the auth-wall check run on THAT url, and selfprofile26's rule run on it unchanged. `saw` gains `self_alias_rewrite` and `self_alias_waited_ms`. Every load is still `SELF_PROFILE_URL`. |
| `server._self_profile_refusal` | the unread refusal now names the wait: "the address stayed on the self alias for the 5 s this server waits for LinkedIn's client-side rewrite..." or "LinkedIn rewrote the self alias's address client-side, to a page that is not a member's profile root". |
| `press.disclose` | a page still at the bare alias is waited on before the pre-press verdict, and the url read again: a press is never made during the rewrite, and an alias that moves to a page that is not his is refused like that page. An alias that never moves is judged as the alias, exactly as before. |
| `scripts/_probe_live_lane_session_2.py` `_in_me_more` | reads his landing as the gate does, after the same wait. |

**THE PAGE MAY VETO; IT NEVER SUPPLIES THE ADDRESS.** The url the page moves
to is waited for and asserted -- a member's profile root whose edit controls
name that member and no other -- and never navigated to or built into an
address.

**For session 14's runner (live-s13 prepares it):** the runner's own phases
that read `page.url` straight after a load of an `/in/me/` address (E18's
`/in/me/?isSelfProfile=true`, E19's overlay) can use the same wait:
`await self_profile.await_rewrite(page)` and then read `page.url`. The wait
polls while the PATH is the alias, whatever the query; the loader and the
press gate call it only for a landing with no marker.

## Lessons (for the orchestrator to harvest)

1. **A wait on an address is invisible to a reader guard built on reads.** The
   leak guard counts locator and script reads, so a function that only polls
   `page.url` is "not driven" and needs a triage line, not a drive: a
   curated drive cannot make it "clean" by that guard's definition.
2. **A baseline writer that runs outside the test runner measures the box,
   not the code.** `--write-baseline` outside pytest has the live 20 s rate
   slot; four readers flipped to "timed out" for no change of theirs. Diff
   a regenerated baseline before committing it, and add a new line by hand
   when the rest is churn.
3. **A refusal sentence that names a shape's literal prefix trips its own
   no-quote test.** Name the rule (`named_profile.MEMBER_ID`), not the
   literal.
4. **`str.lower` is not a segment fold.** It folds the Kelvin sign onto `k`;
   fold ASCII only and keep the closed alphabet, as `self_profile` does.
5. **Park an untracked record outside the tree for a CI push**, then restore
   it: `lane_ci.py push` refuses untracked files, and a record is written as
   the lane runs.
6. **A new test file, a new record and a new admission each meet guards that
   scan the whole corpus**, and no import graph selects them: person-carrying
   constants, cited hashes, debug captures, the census prose's allowlist
   count. Four went red on lane CI after every targeted batch passed. Run
   those four, by name, before the push.
7. **The tool layer turns a `\u` escape in typed input into the character
   itself**: a test meant to hold the escape for a homoglyph held the
   homoglyph. Build such an escape with `chr(92)`, and check new files are
   ASCII before committing.
8. **A matcher that tidies its input can be shown a lookalike.** `strip()`
   before an "exact" comparison let a page-drawn href with an invisible
   character match while the browser went elsewhere. Compare the RAW string,
   and refuse what a browser could read differently, rather than
   re-implementing the browser's parser.
