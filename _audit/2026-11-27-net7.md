## 3. The four facets: N 86, N 88, N 89, N 82 (and N 26b on two of them)

four of them in links on record (section 2.5). `people_search.compose` gains

    argument          LinkedIn key    value accepted                       sent as               evidence of the key
    followers_of      followerOf      ONE member token (ACoAA...)          JSON list             MEASURED: session 12's result cards

    industry_ids      industry        1..5 industry codes (ASCII digits)   JSON list (DERIVED)   MEASURED bare: profile views

`linkedin_people_search_shape` takes the four as parameters and hands each to
`compose` by name; the AST test that every parameter but `include_names`
reaches `compose` holds them. `landing_verdict` reads a JSON string as its text,
so a landing that writes the switch bare (`true`) or a list bare (`96`) reads
`same_values`, never a pass it did not earn. `origin` is never sent. The
follower facet takes one member, as `connections_of` does, under
OTHER-MEMBER-IDS-AS-READS: from the tool's arguments only, never stored, never
echoed, and a slug is refused by shape.
