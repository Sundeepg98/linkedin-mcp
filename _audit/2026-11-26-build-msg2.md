  closed again. Nothing inside the menu is ever pressed by it. A menu left open
  makes every verdict `unknown`. These two calls are the module's only mutating
  call sites: `readonly.SANCTIONED_MUTATIONS` entries 17 and 18, argued beside

## 5. `M C3`, `M C4` (`M C6`, `M C7` riding): NOT BUILT, and why

The media control is drawn -- `Add media` on the feed's composer, and the
dialog it opens draws ONE file input (`u_post_media_open.html`). The build
stops there, for three reasons a lane cannot settle alone:

1. **THE AUDIENCE IS UNREAD ON THIS COMPOSER.** It is `/preload/sharebox/`,
   the composer `linkedin_publish_post` types into -- and that tool REFUSES
   before minting anything (`audience_unread`): the composer's audience
   control's name is redacted by the census rule that keeps other members
   out, so nothing here can say who a post would reach. A photo or a video
   posted there reaches the same unread audience. Building the media post
   would build a second tool that must refuse on the same ground, or lift a
   refusal this lane does not own.
2. **THE FILE WOULD GO IN AFTER A PRESS.** `writes.perform` hands a file to
   the browser before ANY click, by design -- "AND IT IS BEFORE ANY CLICK,
   which is what makes a refusal here harmless". The composer draws no file
   input until `Add media` is pressed (measured: zero before, one after), so a
   media post needs an upload after a press. Even though that press only opens
   a dialog, reordering the drain changes an invariant the upload path
   argues for, in a file two sibling lanes also edit.
3. **NOTHING AFTER THE CHOOSER IS ON DISK.** The editor, the alt-text field
   (`M C7`) and its `Next` are drawn only once a file is chosen, and choosing
   one hands the bytes to LinkedIn -- which only the act may do. Its first
   fire would be that measurement, at his order.
