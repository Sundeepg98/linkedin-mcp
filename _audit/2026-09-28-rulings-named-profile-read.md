# Ruling, 2026-09-28: reading a profile he names

## The question put to him

On 2026-09-28 the orchestrator asked the operator about reading another member's
profile outside an outward act, for example to see which groups a member
belongs to before connecting (`N 178`), or to look up a hiring manager. His own
call of 2026-09-04 had removed the third-party profile pattern from the read
boundary, and `PERMANENTLY_FORBIDDEN` names the act, so only he could reverse
it.

The question named the practice, the risk and the mitigations:
- **The risk:** loading a member's profile can leave that member a
  who-viewed record, and it cannot be undone.
- **The mitigations:**
  - only a profile link or member id he names, never a name read off a page;
  - a single-use confirmation for each view, stating the possible trace;
  - one page per call, with declared fields leaving only as people records;
  - nothing stored.

The same message began: "Why are you asking me? On one hand, why can't you

## What it permits

A read of a member's profile that he names in the call, by link or member id,
under all of these conditions:
- behind the single-use grant;
- the preview states that LinkedIn may show the member the view;
- the declared fields are returned as people records under
  PEOPLE-DATA-MITIGATIONS;
- never for a measurement;
- never aimed by a name read off a page.

It unblocks `N 178` and the same read for any member he names.
