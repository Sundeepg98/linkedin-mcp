## Design (decided, mirroring `connect_from_profile` -- the named-profile write precedent)

All three are **performable WriteSpecs that fire only behind the single-use grant**, off by
default, aimed by the caller's own argument, and whose gate REFUSES before any press when its
target control is not drawn -- the `connect_from_profile` C-P shape (measured surface, measured
anchor, but the fire still needs the operator-named target + a captured control). The preview
loads the target surface, reads its controls live, and:
- `endorse_skill`  / `withdraw_endorsement`: load the named profile through the named-profile door
  (a named outward act, permitted as connect/message are); read the Skills section; require exactly
  one visible per-skill control naming the caller's skill in the state the action is valid from
  (forward: not-yet-endorsed; inverse: endorsed). Not drawn -> refuse, name the missing control.
- `tracker_stage`: load the job-tracker stage the job is CURRENTLY in (read door, admitted for
  saved/applied/draft); find the row by job id; open its row-scoped overflow; press the stage-mark
  item only when exactly one such control is drawn and it belongs to that row. Not drawn -> refuse.

Naming law (`readonly.name_implies_write`): a write tool's name must carry a write verb.
- `linkedin_endorse_skill` -> verb `endorse` OK (already a WRITE_VERB)
- `linkedin_withdraw_endorsement` -> verb `withdraw` OK
- `linkedin_tracker_stage` does not exist: it is the brief's name, and the tool shipped as `linkedin_set_tracker_stage`.
- `linkedin_tracker_stage` -> **NO write verb** ("stage" is not in WRITE_VERBS). Renamed to
  `linkedin_set_tracker_stage` (verb `set`), action `tracker_stage`. This deviates from the brief's
  literal `linkedin_tracker_stage` because the naming law would otherwise reject it; recorded here.

## Round-trip rule (a-round-trip-needs-its-inverse-proven-first)

Both endorsement tools built in one change. Live proof sequence is **endorse then withdraw** (the
inverse proven on the target before the forward press). Offline both refuse on the un-drawn control,
so the inverse (withdraw) is proven as its own refuse-gate first, and the forward (endorse) presses
only when the control is drawn AND its state is the forward-valid one. Neither is fired here (offline).

## Census effect (rows move only by their own cell's bar)

A tool built on synthetic/captured markup moves its row to COVERED-UNFIRED, never PROVEN. Where a
row's cell names a capture I do NOT have, the row stays where it is and I record the missing
capture as its held-by.
- J 54 (tracker stage): built (tool + spec + gate), control uncaptured -> record held-by the
  tracker overflow "Move to" capture.
- N 111 (endorse): built, control uncaptured -> record held-by the named-profile Skills-section
  capture (`outward_classes` endorse_skill CaptureSpec).
- N 113 (withdraw): built as the inverse, control uncaptured -> record held-by the same capture.
- N 112 (several skills at once): NOT served by a one-skill tool -> left as-is, recorded.
Pin re-derivation happens at the end from measured figures (census_completion.py), never summed.
