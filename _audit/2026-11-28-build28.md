## 10. Lessons (for the orchestrator to harvest)

1. A BUILD PUSHED TO LANE CI WITH ONLY ITS KNOWN RED FINDS THE HAND-KEPT TABLES EARLY. Both pushes
   failed on the one test the brief keeps red until banking (the tool-surface pin) and on nothing
   else across the suite, so no unknown registry was left for the certifying run. Push the build
   head before the banking commit when banking is held.
2. A TRIPWIRE THAT SAYS "NOTHING CALLS X" ASSUMES WHICH CALLER COMES FIRST. The P C8 test was
   written for P C8's press; this lane's download was the first caller. It was restated as an
   exact caller list held to its page, not deleted, so the next caller still trips it.
3. A NEW READER'S FIRST LEAK MEASURE CATCHES RAW ATTRIBUTE VALUES. `aria-checked` and
   `aria-expanded` returned verbatim are page text to the guard; map a state to the module's own
   literal at the read.
4. A REFUSING WRITE WITH A FILE TARGET MEETS TWO MORE TABLES: the leak harness's
   `SYNTHETIC_RAW_TARGETS` (missing, every writes reader went undriven for every spec) and
   `test_writes_nine.py`'s shared upload-root fixture (a second fixture making the same temporary
   folder raised `FileExistsError` on all 264 tests).
5. A WRITE TOOL'S PARAMETER MAY NOT BE NAME-SHAPED: `*_name` is refused by
   `test_no_write_is_aimed_by_a_name.py`, so the delete takes `resume`, not `file_name`; a READ
   tool may keep `file_name`. And a read tool's docstring may not hold an unnegated write verb:
   "`Delete` is never pressed" is flagged (the negator follows the verb), "nothing else in the
   menu is ever pressed" is not.
6. EDIT SCRIPTS GO IN FILES, NOT HEREDOCS: two heredoc edits failed to parse and one escape
   (`\x89`) arrived changed; the asserted anchors caught each before anything was half-written.
7. THE LEARNING HEADINGS AND THE CAREER-INSIGHTS HEADINGS ARE DIFFERENT PROBLEMS: Learning's UI
   words matched by keyed shape at once (33 path words, 15 type labels, 15 durations), while the
   insights page's section lines carry his query and match nothing offline.
8. A RULING THAT REGISTERS AN ACT CAN CHANGE ITS CODE, NOT ONLY ITS CITATION. "Any sign that the
   item does more than download ... stops the act" read against the download's after-path found a
   clean-up press (the closing Escape) that could dismiss the very dialog the ruling names. Read
   every clause of a new ruling against what the code does AFTER its sanctioned press, red first.
9. A ROW LEAVING GAP MEETS A TABLE NO BANKING SCRIPT EDITS. `triage_read_gap_rows.TRIAGE` is keyed
   by the read-GAP set it re-derives from the census, so moving `P M4` turned it red while every
   file the banking touched stayed green. Before a banking push, run the tests of each instrument
   that RE-DERIVES a row set from the census (`test_triage_read_gap_rows.py` among them), not only
   the tests of the files edited.
