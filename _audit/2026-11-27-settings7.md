## 11. Lessons (for the orchestrator to harvest)

1. A SHAPE THAT FITS IS NOT A MATCH. Twice a keyed shape fitted the answer
   the orders expected -- `synced-and-imported-contacts` on privacy entry 5,
   `blocked-members` on entry 12 -- and twice the hash said no. Aim candidates
   by shape; decide by hash only.
2. A RED-FIRST RUN MAY FAIL ONLY WHAT THE EDIT IS TO TURN GREEN. The first
   red run of the admissions harness also failed a sibling check, which was
   the test's own wrong expectation (the first substring in the tuple's
   order names the refusal). Read every red in a red-first run, not its count.
3. A CHECKER CAN FORBID WHAT AN ORDER ASKS, AND THE QUEUE'S OWN FORM CAN HOLD
   BOTH. A queue line naming rows another lane re-aims turns `check_next_step`
   red on this branch if its `needs` is `-`; a prose precondition in `needs`
   (a form the queue already used) carries the line until the re-aim merges.
4. A WORDS FIXTURE IS THE EVIDENCE AN ADMISSION NEEDS. An admission whose
   spelling is said to be "drawn" should cite a committed fixture that draws
   it: the contacts admission needed a session-11 fixture no lane had built.
5. A ROW'S MOVE MEETS EVERY TEST THAT NAMES THE ROW, NOT ONLY THE TABLES THAT
   COUNT IT. `P K1` was pinned by name in a 2026-09-28 test whose docstring
   asked to be moved with it; the gates chosen by file (the tool surface, the
   pins, the ledger) did not include it. Before the first push, list every
   test that reads `_audit/_census` and grep the moved row ids in `tests/`.
6. `/tmp` IS THE OS SCRATCHPAD IN GIT BASH. One of this lane's gate loops
   wrote a transient file there before the lane noticed; it was removed, and
   every later loop wrote to the lane's own scratch directory.
